# SHAPE mobile slice

Runs the KataGo human-SL net (`b18c384nbt-humanv0`) on-device for **one fixed position**,
and checks its output against a desktop ONNX reference bundled as an asset.

This is a spike, not the app. It exists to prove the engine can run on Android at all.

## Install

`shape-slice-arm64.apk` — arm64-v8a only (all modern phones), debug-signed, 135 MB.

```
adb install shape-slice-arm64.apk
```

Or copy it to the phone and open it; Android will ask you to allow installs from
this source. It needs no network and no permissions.

## What you should see

A 19×19 board with the opening `Q4 D4 Q16 D16 R14`, a policy heatmap, and a rank
dropdown. Changing rank rebuilds the 192-channel metadata vector in Dart and re-runs
the net. Expected, matching desktop:

| rank | top move | scoreLead |
|---|---|---|
| rank_20k | O3 15.6% | −1.43 |
| rank_5k | O3 18.5% | +1.90 |
| rank_1d | O3 34.6% | +1.72 |
| rank_9d | R3 63.5% | −0.22 |
| proyear_1985 | K17 41.4% | +0.55 |
| proyear_2023 | R3 67.6% | −0.42 |

`vs desktop` should read **MATCH** (~1e-7). That line is the point of the app —
running proves nothing on its own, matching the reference proves the port is correct.

## What it does NOT do

- No board interaction; the position is fixed.
- `bin_input`/`global_input` are precomputed on desktop and shipped as `assets/position.bin`.
  The board/featurizer port is not done, so the app cannot featurize a new position.
- No search (UCT). `scoreLead` here is the raw value head, not a searched score.
- **Timings from an emulator are meaningless** — no NPU, CPU execution provider only.
  Real numbers need a physical device.

## Rebuilding

```
flutter test          # verifies the Dart metadata encoding vs the KataGo reference
flutter build apk --release --split-per-abi --target-platform=android-arm64
```

Assets are regenerated by `tools/onnx_export/export_assets.py`; the model comes from
`tools/onnx_export/export_onnx.py` and lives in `~/.katrain/`.

## Gotchas found the hard way

- **R8 strips ONNX Runtime.** Its native code resolves `ai.onnxruntime.*` by name via
  JNI, so release builds abort at the first `session.run()` with
  `ClassNotFoundException: ai.onnxruntime.TensorInfo`. `android/app/proguard-rules.pro`
  keeps them. The plugin ships no consumer rules.
- **`OrtValue.asList()` returns the tensor's nested shape**, so a `[1,362]` output is a
  List holding one `Float32List`. Flatten it; don't `cast<num>()`.
- **fp16 via `onnxconverter_common` produces an invalid graph** (Cast type mismatch in
  the gpool block). Halving the model needs a native `.half()` export instead.
